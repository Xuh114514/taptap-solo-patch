# 原理：渠道版客户端是怎么被"扣"到本机的

> 看懂了这一页，你就知道补丁为什么只动这三处，也知道它为什么不会影响官服。

## 1. 官方（渠道版）的登录链路

从客户端 `Player.log` 里能直接读到：

```
QuickSDK_cn_win onInitSuccess SDKChannelId: 9999
QuickSDK_cn_win 调用sdk login
url https://sdkapi-of.inutan.com/open/oauth?openId=pcsdk&successUrl=...&channelCode=official
start exe gameName||qgpc&action||callLogin&url||aHR0cHM6...
commandLine = "...\PCSDK_release\PCSDKUI.exe" "gameName||qgpc&action||callLogin&url||..."
RequestFallBackLoginServer over： http://14.103.225.205:18881
SyncGMConfig, getClientVersionAddress: http://dsp-prod-of.inutan.com:18881/dispatch/client_hot_update
RequestRegionInfo response, ... "gate_tcp_ip":"14.103.83.28","gate_tcp_port":11001
```

拆开就是四步：

1. **登录**：游戏进程用 `Process.Start` 拉起 `PCSDKUI.exe`（QuickSDK 的 PC 登录 UI，Qt + WebEngine），
   传一个 `qgpc` 指令串；`PCSDKUI.exe` 打开官网 OAuth 网页。
2. **回传**：你在网页登录成功后，`PCSDKUI.exe` 拿到 token，通过命名管道
   `\\.\pipe\quickpc<游戏PID>` 把 JSON 写回游戏进程。
3. **区服**：游戏拿 token 去 `http://dsp-prod-of.inutan.com:18881/dispatch/...` 换公告、热更、区服信息。
4. **进游戏**：区服响应里带 `gate_tcp_ip/gate_tcp_port`，客户端连官方网关。

所以：
- 原项目替 `PCGameSDK.dll` 的做法，在渠道版上**目标文件都不存在**，自然无效；
- 只要还连着 `sdkapi-of.inutan.com` 和 `dsp-prod-of.inutan.com`，断网就必然起不来。

## 2. 管道协议（补丁的核心）

`PCSDKUI.exe` 里的字符串直接暴露了协议：

```
\\.\pipe\quickpcUnityUI_Server
rec pipe data: %1
rec pipe data, but can not parse json
loginSuccess(QString, QString, QString, QString)
authToken
```

而游戏侧日志打印的是：

```
Pipe server started. Waiting for connection...
OnMessageReceived: {"action":"loginSuccess","params":{"authToken":"...","uid":"...","userToken":"...","username":"...","timeleft":"-1"}}
```

也就是说：**游戏是管道 server（`\\.\pipe\quickpc<游戏PID>`），PCSDKUI 是 client**，先发
`{"action":"init","params":{}}`，登录成功后发 `{"action":"loginSuccess","params":{...}}`。

补丁把 `PCSDKUI.exe` 换成 8KB 的替身：

1. 枚举 `\\.\pipe\` 下所有 `quickpc*` 管道；
2. 连上后发 `{"action":"init","params":{}}`；
3. 紧接着发 `{"action":"loginSuccess","params":{authToken:"local-session", uid:<你的UID>, ...}}`；
4. 游戏日志会打印 `QuickSDK_cn_win onLoginSuccess uid: ... token: local-session`。

游戏拿到这个假 token 后，继续走第 3 步（请求 dispatch）。

## 3. 把 dispatch 指到本机

Lolo 服务端（`server-kit\Lolo.exe`）在 18080 上提供的路由正好对得上：

```
/dispatch/get_notice_list
/dispatch/get_notice_url_list
/dispatch/region_info          <- 返回 gate_tcp_ip / gate_tcp_port
/dispatch/client_hot_update
/dispatch/get_login_url_list
/dispatch/get_client_black_list
```

`region_info` 的实现里直接返回配置里的网关地址，本地配置就是 `127.0.0.1:18100`，
所以客户端拿到响应后会连你自己电脑上的网关。

补丁做两件事把请求送到 18080：

- `hosts`：`127.0.0.1 dsp-prod-of.inutan.com`
- `netsh portproxy`：`127.0.0.1:18881 -> 127.0.0.1:18080`

（为什么不直接把 Lolo 改监听 18881：那样启动器自己的 18080 健康检查会失败，改动面更大。）

## 4. 为什么要动代理旁路

很多人的机器上开着 Clash / V2Ray（`127.0.0.1:7897` 之类）。系统代理一旦生效，
客户端发的 `http://dsp-prod-of.inutan.com:18881/...` 会被代理接手，代理用它自己的 DNS 去解析，
hosts 的 `127.0.0.1` 就被绕过了，于是页面报 `502 Bad Gateway`，游戏里就是「服务器获取失败」。

补丁把 `*.inutan.com`、`14.103.*` 加进「不使用代理」列表（`ProxyOverride`），
让这类请求直连，hosts 才会生效。

## 5. 边界（为什么不会影响官服）

补丁只碰三样东西：

| 改动 | 作用范围 | 影响官服的途径 |
| --- | --- | --- |
| `profiles\solo\client\...\PCSDKUI.exe` | 启动器的**客户端副本** | 无（原客户端目录不动） |
| `hosts` 一行 + `portproxy` | 本机域名解析与本地端口 | 官服客户端也会解析到 127.0.0.1，但它是"连不上"而不是"被改动" |
| `ProxyOverride` | 本机系统代理白名单 | 无 |

`uninstall.ps1` 会把这三样全部还原。

## 6. 已知不完美的地方

- 公告、CDN 图片、支付回调仍然指向官方域名；断网时这些请求会失败（不影响进游戏）。
- 客户端如果是别的渠道/别的版本，`quickpc` 管道名或 dispatch 字段可能不一样，需要重新核对日志。
- 服务端（Lolo）的功能完整度取决于上游实现，不是这个补丁能解决的。
