# 安卓版《开放空间》单机方案调研

> 结论先说：**技术上可行**，因为服务端本身就支持安卓客户端，但比 PC 版多两道坎——**网络重定向**和**SDK 登录伪造**。
> 本文给出三条路线、每条的实际步骤、以及同类游戏已经跑通的案例。

---

## 0. 为什么说"可行"

我翻了 Lolo 服务端的协议定义：

```go
// protocol/proto/common.pb.go
AccountType_AccountType_IOS     = 8888
AccountType_AccountType_Windows = 9999
AccountType_AccountType_Android = 28814
```

服务端**明确区分并支持安卓客户端**（你现在 PC 单机的登录日志里就是 `platform:AccountType_Windows`）。
也就是说：安卓客户端连上 Lolo 之后，协议层是同一套，不需要改服务端。

真正要解决的是安卓客户端这一侧的两件事：

| 坎 | PC 版我们怎么解决的 | 安卓版对应要做什么 |
| --- | --- | --- |
| 让 dispatch 请求打到本机 | 改 Windows 的 hosts + 18881 端口转发 | 改安卓的 DNS/hosts，或者 hook 请求地址，或者让流量走代理 |
| 登录时拿到本地 token | 替换 `PCSDKUI.exe` 为替身，走命名管道回假登录 | hook TapSDK 的登录回调，或者重打包改 SDK 逻辑 |

## 1. 三条路线对比

| | 路线 A：模拟器 + root | 路线 B：真机 + LSPatch | 路线 C：真机 + WiFi 代理 |
| --- | --- | --- | --- |
| 需要 root | 模拟器自带（MuMu/雷电都能开） | 不需要（LSPatch/NPatch 免 root） | 不需要 |
| 需要 PC | 要（跑 Lolo） | 要 | 要 |
| 网络重定向 | 直接改模拟器内 hosts | Xposed 模块 hook URL | 设 WiFi 代理 → PC 上的代理转发 |
| 登录伪造 | Frida / LSPosed hook TapSDK | 自写 Xposed 模块 | mitmproxy 伪造 OAuth（最麻烦） |
| 难度 | ★★☆ | ★★★ | ★★★★ |
| 稳定性 | 好 | 好（装一次即可） | 一般（证书、内网穿透都容易翻车） |
| 推荐度 | **首选（先验证）** | **长期使用** | 只做备选 |

## 2. 路线 A：MuMu / 雷电模拟器（推荐先从这里验证）

### 为什么模拟器最省事

- 模拟器可以开 root，hosts 随便改
- 支持装 LSPosed（MuMu 12 内置"Magisk/root"）
- Frida 可以直接 attach（作者本人当年就是用 MuMu 渠道服抓包的，见 Lolo README 的"渠道服登录与数据保存经验"）

### 步骤

**① PC 侧：把服务端暴露到局域网**

```powershell
powershell -ExecutionPolicy Bypass -File C:\kfkj\of-local\android\lan-server.ps1 -Action on
```

它会：
- 备份 `profiles\solo\config.json`
- 把 `HttpNet.InnerIp` 改成 `0.0.0.0`、`InnerPort` 改成 `18881`
- 把 `GateWay.OuterIp` / `LogServer.OuterIp` 改成你 PC 的局域网 IP
- 放行防火墙 TCP 18881 / 18100 / 18200
- 直接起 `Lolo.exe`，并打印安卓要填的 IP

**② 模拟器侧：把域名指到 PC**

MuMu 12 打开 root 后，在模拟器里改 hosts（`/system/etc/hosts`）：

```
192.168.x.x   dsp-prod-of.inutan.com
```

改法（任选）：
- 模拟器自带的"文件管理器 + root 权限"直接编辑
- `adb root && adb remount && adb shell "echo '192.168.x.x dsp-prod-of.inutan.com' >> /system/etc/hosts"`

**③ 登录伪造**

装 Frida（模拟器里跑 `frida-server`），先用侦察脚本看类名：

```bash
frida -U -f <包名> -l probe.js --no-pause
```

它会打印：TapSDK 相关类、OkHttp 请求、内存里有没有 `dsp-prod-of.inutan.com`。
拿到类名后，hook TapSDK 的登录方法，直接回调成功（token 随便填，Lolo 的 `CheckToken: false` 不校验）。

**④ 连进去看日志**

模拟器启动游戏，PC 上看：

```
C:\kfkj\OverFieldLauncher-portable\profiles\solo\logs\lan-*.log
```

出现 `VerifyLoginToken ... verify success` + `PlayerLogin ... 登录成功` 就是通了。

## 3. 路线 B：真机 + LSPatch（免 root，长期用这个）

同类的成功案例就是这个思路：

- [AnimeGamesProxy](https://github.com/Xuoos/AnimeGamesProxy) —— 一个 Xposed 模块，专门把各种动漫手游的请求重定向到私服。**它已经支持"开放空间（TapTap）"**（目前功能是"启用 GM"），说明这游戏的安卓包已经有模块在 hook 了。
- 它明确写了免 root 用法：**LSPatch** 或 **NPatch（推荐）**，把模块塞进 APK 重打包安装。
- 同时它也写了"不支持在 PC 模拟器中运行"——所以路线 A 用模拟器时要注意，模块方案更适合真机。

要做的事：

1. PC 侧跑 `lan-server.ps1`
2. 真机上用 LSPatch/NPatch 把 APK 打上你的模块
3. 模块里做两件事：
   - hook TapSDK 登录 → 回假 token
   - hook 网络请求 → 把 `dsp-prod-of.inutan.com:18881` 换成 `PC_IP:18881`
4. 装改好的 APK，登录进游戏

> 这条路要写一个 Android 模块（Java/Kotlin + Xposed API），我可以按你提供的 APK 写出来。

## 4. 路线 C：WiFi 代理（不需要 root，但最折腾）

这是 [Grasscutters on Android](https://github.com/kostas214/Grasscutters-on-android) 用的思路，人家把原神跑通了：

1. 手机上跑服务端（Nix-on-Droid）或者连 PC 的服务端
2. WiFi 设置里填**手动代理**：`127.0.0.1:8080`（或 PC 的 IP）
3. 代理用 mitmproxy，访问 `mitm.it` 装 CA 证书
4. 游戏流量全部走代理 → 代理把请求转给本地服务端

对应到开放空间：

1. PC 上跑 mitmproxy（或我写的小代理），把 `dsp-prod-of.inutan.com:18881` 转发到 `127.0.0.1:18881`
2. 手机 WiFi 代理填 `PC_IP:8080`
3. 手机装 mitmproxy CA（Android 7+ 需要装到系统证书区，或者用 apk-mitm 重打包让 APK 信任用户证书）
4. 登录这一段仍然要伪造——可以把 `sdkapi-of.inutan.com` 的 OAuth 响应也伪造掉，但要先抓一次真实登录看返回格式

**这条路我不推荐作为第一选择**，因为：证书、Android 版本限制、SDK 的 HTTPS 校验，每一个都可能卡住。

## 5. 三条路都要面对的"登录伪造"细节

PC 版我们是替换 `PCSDKUI.exe`，安卓版等价物是 **TapSDK 的登录回调**：

```
TapTapSdk.login(activity, callback)  ->  TapTapResult<TapTapAccount>
```

要让它直接成功，通常 hook 两处：

1. `TapTapSdk.login(...)` —— 不请求网络，直接调 `callback.onSuccess(...)`
2. 构造一个 `TapTapAccount`（字段一般有 `accessToken` / `openId` / `unionId` / `name`），用反射 `newInstance` 填假值

关键点：**Lolo 的 `config.json` 里 `GateWay.CheckToken = false`**，所以 gateway 不校验 token，随便填都行。这一点和 PC 端 `local-session` 完全一样。

难点在于 TapSDK 每个版本的类名/字段名会变，所以**必须拿到你手上这个 APK 才能写死**。

## 7. 现实预期

| 项目 | 预期 |
| --- | --- |
| 能不能连上服务端 | 能，协议层已验证支持 Android |
| 能不能完全离线 | 能，前提是登录 hook 成功（和 PC 端一样） |
| 工作量 | 模拟器路线 1～2 小时能验证；真机免 root 要写模块，半天到一天 |
| 风险 | 游戏加固（FairGuard）、TapSDK 版本变化、Android 14 的证书策略 |

> 顺带说明：安卓版是否能拿到**和你 PC 单机同一个存档**，取决于 UID 一致——两边都填同一个 UID（比如 1000000）就共用同一个账号数据，因为存档在 PC 的 `profiles\solo\db\lolo.db` 里。
